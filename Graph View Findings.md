## Goal
Find a narrow set of components for the teaching vehicle that connect with each other as much as possible. This note records what we found while testing Obsidian's graph view as a tool for that.

## How Obsidian graph view works
- Each **note (file)** is one dot. Each **internal link** between two notes is one line.
- Headings inside one file are not dots. `Preliminary Research.md` is a single dot no matter how many sections it has.
- The more notes link to a note, the bigger its dot.
- Useful settings:
	- **Arrows** (Display): shows which note links to which.
	- **Groups**: colour dots by folder or tag, e.g. `path:"Drivetrain Map"`, `tag:#component`, `tag:#type`.
	- **Local graph**: only the notes connected to the open note.
	- **Existing files only** (Filters): hides links to notes that don't exist yet.
- Limitations:
	- Lines can't have labels (e.g. "via CV shaft").
	- All links look the same, so "used together" and "alternative to" can't be told apart on the graph.
	- Layout is automatic.
	- It only draws connections. It can't count them or pick the best set.
- `.obsidian/graph.json` is tracked in git and Obsidian saves the zoom level into it, so just using the graph changes that file. Consider adding it to `.gitignore` like `workspace.json`.

Source: [Obsidian Help – Graph view](https://obsidian.md/help/plugins/graph)

## Options considered

| Option | How it works | Pros | Cons | Result |
| ------ | ------------ | ---- | ---- | ------ |
| Mermaid diagram | `mermaid` code block inside a markdown note | Stays in the same file; lines can have labels | Links inside diagrams don't show in graph view; wide diagrams get cramped | Tested, not preferred |
| Canvas | Separate `.canvas` file with cards and hand-drawn connections | Labels and colours on lines; no separate notes needed | Layout by hand; separate file | Not tested |
| Graph view | One note per part, linked to what it connects to | Builds the network automatically; local graph per part | Needs separate notes; no labels | **Chosen** |

Sources: [Obsidian Help – Advanced syntax (Mermaid)](https://obsidian.md/help/advanced-syntax), [Obsidian Help – Canvas](https://obsidian.md/help/plugins/canvas)

## How the Drivetrain Map was set up
For the demo, a `Drivetrain Map/` folder had one note per item in the README scope list, plus Engine, Electric Motor and Wheels (not in the scope list, added so the drivetrain has a start and an end).

- Every note had a tag: `component`, `layout`, `ev`, `advanced` or `type`.
- **Differentials** and **transfer cases** also had one note per type (from the types tables in `Preliminary Research.md`). Layout links sat on the types rather than the general part, e.g. Ring-and-pinion Differential ↔ RWD, Epicyclic Differential ↔ AWD.
- Links went both ways, and type links carried a short reason.
- 39 notes and 86 connections. The folder was removed after the demo; every note's connections are in the appendix below so it can be recreated.

Example note (`Ring-and-pinion Differential.md`):
```
---
tags:
  - type
---
Type of: [[Differential]]

Connects to:
- [[Drive Shaft]]: turns drive 90° from the drive shaft to the half shafts
- [[RWD]]: common use: RWD
```

To add types for another part: create a note with `Type of: [[Part]]`, add it to the parent's `Types:` line, and list what it connects to.

Connections for differentials and transfer cases come from our research. The rest (e.g. engine → clutch → gearbox) are general drivetrain layout and still need checking by each section's owner.

## Connection analysis (script)
Graph view can't pick a set, so a short Python script read the notes, counted connections, and searched for the small sets with the most links between their members.

Most connected notes: Differential (17), Transfer Case (15), Drive Shaft (10), Gearbox (9), 4x4 (9).

| Set size | Best set | Pairs linked |
| -------- | -------- | ------------ |
| 4 | CV Shaft, Steering, Suspension, Wheels | 6 of 6 |
| 5 | Coupling, Differential, Drive Shaft, Gearbox, Transfer Case | 10 of 10 |
| 6 | The 5 above + CVT | 13 of 15 |
| 8 | The 6 above + Clutch + one differential or transfer case type | 18 of 28 |

Sizes 6 and 8 only searched the 25 most connected notes.

Why these results can't be used yet:
1. **Some links mean "alternative", not "used together".** Gearbox and CVT both end up in the 6-set, but a vehicle uses one or the other.
2. **Connected doesn't mean it drives.** The 5-set has no power source, wheels or steering.
3. **Scores favour what has been researched.** Differentials and transfer cases score highest partly because they have type notes.
4. **Suitability isn't in the graph.** Printability and demonstratability (Teaching Platform notes) aren't counted.

## Split links demo ("Alternative to")
Tested adding an `Alternative to (<choice>, pick one):` section to notes, separate from `Connects to:`, then reverted it. Groups used:

| Choice | Pick one of |
| ------ | ----------- |
| Power source | Engine, Electric Motor |
| Between engine and gearbox | Clutch, Torque Converter |
| Transmission | Gearbox, CVT |
| Engine drive layout | FWD, RWD, AWD, 4x4 |
| EV configuration | Single-Motor Single-Axle, Dual-Motor Single-Axle, Dual-Motor Dual-Axle |
| Differential gear design | Ring-and-pinion, Epicyclic, Spur-gear |
| Differential traction behaviour | Locking, Limited-slip |
| Transfer case operation | Part-time, Full-time, Part-/Full-time Hybrid |
| Transfer case drive | Gear-driven, Chain-driven |
| Transfer case housing | Married, Divorced |
| Transfer case shift | Manual shift-on-the-fly, Electronic shift-on-the-fly |

Findings:
- Types have more than one kind of choice. Gear design and traction behaviour are separate, so a ring-and-pinion differential can also be limited-slip.
- Engine layouts and EV configurations overlap (a dual-motor, dual-axle EV is also AWD), so they were kept as separate groups.
- Clutch is only an alternative to the torque converter in the engine-to-gearbox position. Clutch packs in differentials and transfer cases are still "connects to".
- Graph view draws alternative links the same as connections, so the split only shows in the note text (and to a script). Writing alternatives as plain text instead of links would keep them off the graph.

## Next steps
1. Decide whether to bring the Drivetrain Map back, and whether to use "Alternative to" sections in the notes.
2. Decide the must-haves for the vehicle (e.g. one power source, wheels, steering) so the analysis only returns sets that make a working vehicle.
3. Optionally score each note for the Teaching Platform criteria (e.g. `printability`, `demo`) so the analysis prefers teaching-friendly parts.
4. Each owner adds type notes and checks the general connections for their section.
5. To see connection counts inside Obsidian, the community plugin *Dataview* can show a table of notes sorted by number of links. Picking the best set still needs a script.
